# V0.2.1 Data Quality Gate and Archetype Test Strategy

## Purpose
Before any LLM agent runs, the site must pass a deterministic data-quality assessment. The gate separates source availability from severity so that optional data does not accidentally block the pipeline.

## Source-level statuses
- `COMPLETE`: expected data is present and usable.
- `PARTIAL`: some usable data exists but important fields/coverage are incomplete.
- `CONFLICT`: records disagree or relationships cannot be reconciled deterministically.
- `STALE`: data exists but is older than the approved freshness threshold.
- `NOT_APPLICABLE`: source is legitimately irrelevant to the selected site.
- `MISSING`: no applicable source record exists.

## Severity
- `BLOCKING`: downstream agent processing must stop.
- `WARNING`: pipeline can continue only with review/acknowledgement.
- `INFORMATIONAL`: absence or condition is acceptable and recorded for transparency.

## Examples
- Owned building with no lease -> `NOT_APPLICABLE / INFORMATIONAL`.
- Leased building with no lease -> `MISSING / BLOCKING`.
- Missing strategic context -> `MISSING / INFORMATIONAL`.
- Missing component register -> `MISSING / WARNING`.
- Lease linked to an unknown occupancy -> `CONFLICT / BLOCKING`.
- Multi-occupant building with valid IDs -> not a conflict; preserve the relationships.

## Gate states
- `BLOCKED`: at least one blocking missing/conflict/stale condition.
- `REVIEW_REQUIRED`: no blocking issue, but at least one warning condition.
- `VALIDATED`: no blocking or warning condition.

## Eight synthetic archetypes
1. Long-term owned building.
2. Leased site approaching lease expiry.
3. Multi-service-point building.
4. High-FCI aging building.
5. Site with future initiative overlap.
6. Site with active-project scope overlap.
7. Accessibility-driven site with both non-compliant and unknown criteria.
8. Deliberately broken lease/occupancy association.

## Evaluation philosophy
Tests assert expected *behaviour*, not exact language. Later A->E evaluations should check invariants such as lineage preservation, duplicate-scope avoidance, lease constraint surfacing, detention-band use, strategic-context treatment, and preservation of `unknown` accessibility status.
