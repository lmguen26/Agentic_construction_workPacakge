# V0.2.2 Agent Evaluation Harness

## Purpose
V0.2.2 tests the agentic methodology before production source schemas are available. It does not attempt to prove that synthetic recommendations are professionally correct. It proves that the pipeline preserves evidence, respects deterministic gates, uses relevant context, and keeps stage ownership clear.

## Execution pattern

```text
Synthetic source domains
        |
        v
Data Quality Gate
        |
        +-- BLOCKED -> stop before Agent A
        |
        v
Canonical site_context.json
        |
        v
A Opportunity Normalizer
        |
        v
B Work Package Builder
        |
        v
C Cost Engine
        |
        v
T Strategy Recommender
        |
        v
E Executive Summary
        |
        v
Behavior Evaluator
```

## Golden reference fixtures
Run:

```bash
python -m src.evaluation.reference_fixture_builder
```

This creates `examples/archetypes/reference_runs/<building_id>/` with:

- `site_context.json`
- `stage_A.json`
- `stage_B.json`
- `stage_C.json`
- `stage_T.json`
- `stage_E.json`
- `run_status.json`

The intentionally conflicted archetype `BLDG-A8` generates only the context and run status because the deterministic gate blocks downstream execution.

## Evaluation philosophy
Do not compare exact LLM sentences. Test stable business behavior instead.

Examples:
- every generated opportunity remains traceable to its deficiency;
- a multi-service-point building is not flattened;
- active lease constraints remain visible at Agent T;
- future initiatives are considered during bundling/blending;
- active project scope is surfaced before a duplicate work package is recommended;
- accessibility `unknown` remains `unknown`;
- high FCI triggers strategy review;
- strategic context informs recommendations but does not overwrite authoritative facts;
- Agent B owns work-package creation;
- Agent E summarizes and never creates new work packages.

## Current archetypes
1. Long-term owned.
2. Lease expiry approaching.
3. Multi-service-point building.
4. High-FCI aging building.
5. Future initiative overlap.
6. Active project overlap.
7. Accessibility-driven site.
8. Association conflict / blocked pipeline.

## Transition to actual Copilot outputs
The reference artifacts are deterministic golden fixtures. The next testing mode replaces one stage at a time with a real GitHub Copilot custom-agent output and runs the same semantic evaluator against it.

Recommended progression:
1. Replace synthetic Agent A only; keep B-E golden.
2. Validate Agent A against contract and behavior tests.
3. Replace Agent B, then C, T and E sequentially.
4. Record model, prompt version, rule version and evaluation result in `pipeline_run.json`.

This isolates failures and prevents a downstream agent from hiding an upstream defect.
