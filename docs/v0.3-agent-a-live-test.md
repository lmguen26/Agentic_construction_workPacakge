# V0.3 — Live Agent A test in VS Code

V0.3 replaces only the synthetic Agent A stage with a live GitHub Copilot custom-agent run. B, C, T and E remain reference fixtures until Agent A is stable.

## Why isolate Agent A
Agent A owns one bounded transformation: validated deficiency -> normalized opportunity. Testing this stage independently makes failures attributable and measurable.

## VS Code setup
VS Code discovers workspace custom agents in `.github/agents` and prompt files in `.github/prompts`. Open the repository root as the workspace.

## Manual test
1. Check out branch `v0.3-agent-a-live`.
2. Open GitHub Copilot Chat.
3. Invoke `/run-agent-a-live building_id=BLDG-A1`.
4. Review the JSON output before accepting any handoff.
5. Save the output under `examples/archetypes/live_agent_a/BLDG-A1.opportunities.json` if Copilot has not written it directly.
6. Run the evaluator/tests.
7. Repeat against BLDG-A2 through BLDG-A7. BLDG-A8 must stop upstream because its relationship data are intentionally blocked.

## Acceptance criteria
Agent A is considered stable enough to move to Agent B when repeated runs satisfy:
- 100% deficiency-to-opportunity traceability;
- no changed source identifiers or source factual values;
- no cost indexation or indirect-cost calculation;
- no work-package, bundling, blending or strategic recommendation output;
- explicit assumptions/exceptions instead of invented facts;
- no suppression of a deficiency because of a project, initiative, lease, detention horizon or strategic context;
- stable contract-shaped JSON that downstream deterministic validation can parse.

## Model comparison
The evaluator is wording-independent. The same test can therefore be run with different Copilot models. Capture model name, prompt/agent commit SHA and evaluator result in the run manifest when comparing results.

## Promotion rule
Do not automate the A -> B handoff (`send: true`) until Agent A passes the archetype suite consistently. Human review remains the V0.3 default.
